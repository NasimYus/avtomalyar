# Автомаляр — программа лояльности

Веб-система учёта покупок дилеров и программа лояльности для магазина
автомалярной продукции «Автомаляр»: админ-панель + личный кабинет дилера.

**Текущий статус — этап 2 завершён:** фундамент, авторизация,
админ-панель со справочниками, дилерами, покупками и акциями (расчёт
рейтинга и публикация итогов), а также личный кабинет дилера.

## Что уже работает

- Вход для админа и дилера (JWT в httpOnly-cookie), разграничение ролей.
- Админ-панель: дашборд (включая число активных акций и сколько из них ждут
  подведения итогов), дилеры с карточкой (данные, история покупок, участие в
  акциях), покупки, справочники (города, уровни, призы).
- Автоматические пересчёты: накопленная сумма дилера и его уровень
  обновляются при любой правке покупок — в той же транзакции.
- Уровни — лестница любой длины (3, 10, …). У каждого уровня свой «материал»
  из 10 (бронза, серебро, золото, платина, изумруд, сапфир, аметист, рубин,
  бриллиант, оникс): по умолчанию он подбирается по месту уровня в лестнице,
  админ может выбрать его вручную. Эффекты зависят от места: верхняя половина
  лестницы переливается, высший уровень светится и носит корону. В кабинете —
  медаль с номером уровня, прогресс в цвете следующего уровня с подбадривающей
  фразой, «Путь дилера» со всеми уровнями и поздравление с новым уровнем.
- Фото призов кадрируются при загрузке: админ перетаскивает и масштабирует
  фото в рамке 4:3 (или вписывает целиком — поля станут белыми), и на сервер
  уходит JPEG 1200×900. Поэтому на всех карточках призы выглядят одинаково,
  какого бы размера ни было исходное фото. Уже загруженное фото можно
  перекадрировать.
- Логин и пароль дилера генерируются при создании и показываются один раз;
  пароль можно только сбросить.
- Акции: условия участия (город, уровень, порог закупок), призы по местам,
  жизненный цикл «черновик → активна → итоги рассчитаны → опубликована →
  архив».
- Итоги акции считаются по правилам ТЗ (сумма за период, при равенстве —
  кто достиг её раньше), никогда не публикуются автоматически: админ
  проверяет рейтинг, может поправить места и призы, и только затем
  публикует — после публикации итоги заморожены.
- Кабинет дилера (верстается от мобильного экрана): накопленная сумма,
  уровень и прогресс до следующего, история покупок, свои акции с местом
  в рейтинге и призом, а также блок «Что впереди» — акции, которые ещё не
  начались или условия которых дилер пока не выполнил, с подсказкой, чего
  именно не хватает. Рейтинг чужой акции при этом не показывается.
- Интерфейс на русском и таджикском, переключение в сайдбаре. И в кабинете,
  и в админке на таджикский переводятся и названия — города, уровни, призы,
  акции. Ошибки сервера приходят с машинным кодом причины (`reason`) и
  показываются на языке интерфейса; тест следит, чтобы каждый ключ из кода
  был в обеих локалях.
- Адаптивная вёрстка везде: в админке на телефоне — верхняя панель с меню,
  таблицы превращаются в карточки; кабинет дилера на десктопе раскладывается
  в две колонки.

## Стек

- **Backend**: Go, chi, pgx/sqlc, PostgreSQL, golang-migrate, JWT + bcrypt.
- **Frontend**: React + TypeScript + Vite, Feature-Sliced Design, TanStack
  Query, Tailwind CSS, react-i18next (ru/tg).
- **Инфраструктура**: Docker Compose, GitHub Actions CI.

## Тестовый стенд на сервере

Показать заказчику: `sudo ./deploy/install.sh` на любом VPS с Ubuntu
поднимает всё с HTTPS и демо-данными одной командой — см.
[`deploy/README.md`](deploy/README.md).

## Быстрый старт (Docker)

```bash
cp .env.example .env
# отредактируйте .env — как минимум задайте JWT_SECRET
make up
```

В отдельном терминале, пока контейнеры подняты:

```bash
make migrate-up
make seed-admin
make seed-demo   # необязательно: демо-данные для демонстрации
```

`make seed-admin` выведет логин и пароль администратора один раз —
сохраните их. Пароль можно задать заранее: `ADMIN_PASSWORD=… make seed-admin`.

Приложение будет доступно на `http://localhost` (фронтенд проксирует
`/api` и `/media` на backend), backend напрямую — на `http://localhost:8080`.

## Локальная разработка без Docker

Postgres поднимается из compose, backend и frontend запускаются локально.
Порт Postgres на хосте — **5433** (чтобы не конфликтовать с локально
установленным Postgres); внутри docker-сети это по-прежнему 5432.

```bash
docker compose up -d postgres
```

Backend:

```bash
cd backend
export DATABASE_URL="postgres://avtomalyar:avtomalyar@localhost:5433/avtomalyar?sslmode=disable"
export JWT_SECRET=dev-secret UPLOAD_DIR=./uploads
go run ./cmd/api          # http://localhost:8080
```

Frontend (Vite проксирует `/api` и `/media` на `localhost:8080`):

```bash
cd frontend
npm install
npm run dev               # http://localhost:5173
```

Витрина UI-компонентов — `http://localhost:5173/admin/ui-kit`.

## Полезные команды

| Команда | Что делает |
|---|---|
| `make up` / `make down` | Поднять/остановить окружение через Docker Compose |
| `make lint` | Линтеры backend (golangci-lint) и frontend (ESLint, Prettier, Steiger) |
| `make test` | Тесты backend (`go test`) и frontend (Vitest) |
| `make migrate-up` / `make migrate-down` | Применить/откатить миграции БД |
| `make sqlc` | Сгенерировать типобезопасные запросы из `backend/queries/*.sql` |
| `make seed-admin` | Создать первого администратора |
| `make seed-demo` | Заполнить БД демо-данными (6 городов, 5 уровней, 5 призов, 12 дилеров, ~74 покупки) |
| `make e2e` | Сквозные тесты Playwright против запущенного стенда (см. «E2E-тесты») |

Для `make lint` локально нужен установленный `golangci-lint`:

```bash
go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@latest
```

## Дизайн

Визуальный язык перенесён из дизайн-системы «Автомаляр»: холодный фон
`#F3F3F5`, белые карточки с радиусом 30px, красный `#FF0009` как цвет
действия (со свечением), зелёный — «участвует/допущен», жёлтый —
«осталось/золото». Шрифт Montserrat подключён локально через
`@fontsource` — внешних CDN в рантайме нет.

Все токены — в [`frontend/src/app/styles/index.css`](frontend/src/app/styles/index.css),
компоненты — в [`frontend/src/shared/ui`](frontend/src/shared/ui).

## E2E-тесты

Папка `e2e/` — сквозные тесты на Playwright против настоящего стенда
(frontend + API + PostgreSQL с демо-данными). Они проходят то, что делают
люди: вход и права доступа, справочники, заведение дилера и покупки с
пересчётом уровня, полный цикл акции от создания до архива — с проверкой
кабинета дилера на обоих языках, — а также вёрстку всех страниц на семи
экранах, от 360px Android до 1920px десктопа.

```bash
# стенд должен быть поднят и заполнен: make up, make migrate-up,
# ADMIN_PASSWORD=… make seed-admin, make seed-demo
cd e2e && npm ci && npx playwright install --with-deps
E2E_ADMIN_PASSWORD=… E2E_BASE_URL=http://localhost npx playwright test
```

- `E2E_ALL_BROWSERS=1` добавляет Firefox и WebKit (движок Safari и всех
  браузеров на iPhone). В CI так и запускается — job `e2e`.
- Отчёт: `npx playwright show-report`.
- Тесты создают свои записи с префиксом «E2E» — запускать их стоит на
  тестовой, а не на рабочей базе.
- Против стенда из `deploy/` (за Caddy): `E2E_BASE_URL=https://…`,
  `E2E_BEHIND_PROXY=1` (тест лимита входа там проверяется вручную — за прокси
  адрес клиента не подделать), для самоподписанного сертификата
  `E2E_IGNORE_HTTPS_ERRORS=1`.

## Поддерживаемые браузеры

Сборка рассчитана на браузеры не старше трёх лет: Chrome/Edge 111+,
Firefox 114+, Safari и iOS 16.4+ (iPhone 8 и новее), Samsung Internet 22+.
Это минимум Tailwind CSS 4 и цель сборки Vite по умолчанию. Для
полупрозрачных цветов в CSS есть запасные значения, поэтому на
пограничных версиях вёрстка не разваливается.

## Переменные окружения

См. `.env.example`. Обязательные для запуска — `JWT_SECRET` (в production
длинное случайное значение) и настройки PostgreSQL. `UPLOAD_DIR` задаёт
папку для фото призов (в Docker — том `/data/uploads`).

`AUTH_COOKIE_SECURE` (по умолчанию `true`) — cookie сессии уходит только по
HTTPS. На стенде, который открывают по голому HTTP через IP или имя хоста
(не `localhost`), поставьте `false`, иначе браузер отбросит cookie и после
входа сразу выкинет обратно. За HTTPS оставляйте `true`.

За nginx из `frontend/` бэкенд берёт адрес клиента из `X-Real-IP` (только от
прокси с частного адреса) — на нём держится ограничение попыток входа. Если
перед приложением стоит свой прокси, он тоже должен передавать `X-Real-IP`.
