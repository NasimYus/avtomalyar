# Отчёт о тестировании — этап 3, п. 1

Функциональное тестирование всех модулей и кросс-браузерная / кросс-девайсная
проверка адаптивности. Дата: 26.09.2026.

## Как тестировали

- **Настоящий стенд**, не заглушки: PostgreSQL 16, миграции с нуля (и откат
  всех миграций с повторным применением), `seed-admin` + `seed-demo`, API на Go,
  собранный фронтенд.
- **Автоматические сквозные тесты** (`e2e/`, Playwright) — проходят интерфейс
  так, как это делают администратор и дилер, и проверяют результат и в админке,
  и в кабинете.
- **Юнит-тесты**: backend `go test`, frontend Vitest.
- **Линтеры** в тех же версиях, что в CI: golangci-lint v2.14.0, ESLint,
  Prettier, Steiger, `tsc`.

## Функциональные сценарии

**Вход и права доступа**
- неверный пароль — понятная ошибка;
- вход админа, сессия переживает перезагрузку, выход;
- без входа админка и кабинет недоступны;
- дилер попадает в кабинет, в админку его не пускает;
- API админки: дилеру — 403, гостю — 401;
- отключённый дилер не может войти, открытая сессия обрывается сразу;
- подбор пароля упирается в лимит, но вход других пользователей не блокирует.

**Справочники**
- города: добавить, переименовать, удалить; город с дилерами удалить нельзя (с
  объяснением); пустое название не сохраняется;
- уровни: добавить с выбранным цветом, повтор порога отклоняется, удалить;
- призы: фото любой формы кадрируется в 4:3, на сервер уходит 1200×900.

**Дилер, покупки, уровень**
- админ заводит дилера, получает логин и пароль; дилер находится поиском;
- новый дилер видит кабинет: уровень 1 из 5, прогресс, пустую историю;
- покупка «из будущего» не принимается;
- покупка поднимает уровень — форма предупреждает заранее, список дилеров и
  кабинет показывают новый уровень и сумму;
- на новом уровне дилера поздравляют один раз;
- кабинет целиком переводится на таджикский (включая названия уровней),
  выбор языка сохраняется;
- удаление покупки возвращает уровень;
- новый пароль заменяет старый;
- дилера с покупками удалить нельзя, без покупок — можно.

**Полный цикл акции** (критерий приёмки этапа 2)
- создание: период, город, призы по местам;
- дилер не видит черновик;
- запуск;
- расчёт: порядок по сумме за период, при равенстве выше тот, кто набрал
  сумму раньше; покупки вне периода не учитываются;
- до публикации дилер итогов не видит;
- корректировка: место и приз вручную, пометка «правка»;
- публикация замораживает итоги; выдача приза отмечается;
- победитель видит место и приз, рейтинг открыт и окончательный;
- другой участник видит свой приз, в том числе на таджикском;
- архив: акция уходит из работы, но остаётся у дилеров с итогами.

## Найденные ошибки и что исправлено

| # | Проблема | Где проявлялась | Исправление |
|---|---|---|---|
| 1 | Cookie сессии всегда с флагом `Secure`. | На стенде по HTTP через IP браузер отбрасывал cookie — после входа админку выкидывало на первом же запросе. | Флаг настраивается: `AUTH_COOKIE_SECURE` (по умолчанию `true`). Проверено: по IP вход работает. |
| 2 | Лимит попыток входа считался по IP соединения, а за nginx это IP самого nginx. | Все дилеры делили одну «корзину»: после 5 входов подряд у любых людей остальные получали «слишком много попыток». Успешные входы тоже тратили лимит. | Адрес клиента берётся из `X-Real-IP` (только от прокси с частного адреса, подделать снаружи нельзя); считаются только неудачные попытки. Покрыто юнит- и e2e-тестами. |
| 3 | Кнопка «Скопировать» логин/пароль падала с ошибкой. | Стенд по HTTP: там нет Clipboard API. | Общий `copyText` с запасным способом. Проверено по HTTP. |
| 4 | Подтверждение «Итоги опубликованы» иногда не появлялось (примерно 1 раз из 8). | Итоги публиковались, но админ не видел подтверждения: карточка публикации исчезала раньше, чем приходил ответ. | Подтверждение не зависит от карточки. После исправления — 100 прогонов подряд без сбоя. |
| 5 | Дашборд вылезал вбок на 60px. | Планшет в портрете (768px). | Сетка больше не растягивается под таблицу. |
| 6 | На iPhone страница увеличивалась при каждом тапе в поле ввода. | iOS Safari масштабирует поля со шрифтом меньше 16px. | Только для iOS поля 16px. *Проверено по документации, на живом iPhone — нет.* |
| 7 | У модальных окон не было доступного имени. | Экранные дикторы. | Заголовок окна связан с ним (`aria-labelledby`). |
| 8 | CI не был зелёным ни разу. | Линтер бэкенда не запускался (экшен v6 не поддерживает golangci-lint v2), `npm ci` во фронтенде падал из-за рассинхрона lock-файла. | Экшен обновлён до v8, lock-файл пересобран; локально `npm ci` с нуля и golangci-lint v2.14.0 проходят. |
| 9 | В конце README лежали логин и пароль демо-дилера. | Случайная вставка в одном из прошлых коммитов. | Удалены. В истории git они остались — это пароль из чьего-то локального демо-сида; если эта база где-то развёрнута, пароль этого дилера стоит сбросить. |

## Что стоит проверить руками на реальных устройствах

Автотесты не заменяют нескольких минут с настоящими телефонами:

- **iPhone (Safari)**: вход, ввод суммы покупки (нет ли увеличения страницы),
  выбор фото приза из галереи/камеры, нативный выбор даты.
- **Android (Chrome)**: то же; нижнее меню кабинета не перекрывается
  системными кнопками.
- **Таджикские тексты** — показать носителю языка.
