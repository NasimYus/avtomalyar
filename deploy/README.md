# Тестовый стенд для заказчика

Всё приложение — база, API, фронтенд и HTTPS — поднимается на любом сервере
с Ubuntu/Debian **одной командой**. Сертификат выпускается сам (Let's
Encrypt через Caddy), домен покупать не обязательно.

## 1. Сервер

Подойдёт любой VPS:

- **Ubuntu 22.04 или 24.04**, 1–2 vCPU;
- **2 ГБ памяти** (на 1 ГБ скрипт сам добавит swap, но сборка будет медленнее);
- 20 ГБ диска;
- открыты порты **80 и 443**.

Примеры: Hetzner Cloud CX22 (~4 €/мес), DigitalOcean Basic 2 GB (~12 $/мес),
Timeweb Cloud или Selectel (оплата в рублях), либо любой хостинг в
Таджикистане с VPS. Для демо хватит самого дешёвого тарифа с 2 ГБ.

## 2. Установка

Зайти на сервер по SSH и выполнить:

```bash
git clone https://github.com/NasimYus/avtomalyar.git
cd avtomalyar
sudo ./deploy/install.sh
```

Скрипт сам:

1. поставит Docker, если его нет;
2. придумает пароли (база, JWT, админ) и сохранит их в `deploy/.env`;
3. соберёт и запустит всё, применит миграции;
4. создаст администратора и заполнит демо-данными: 6 городов, 5 уровней,
   5 призов, 12 дилеров, ~74 покупки и акции во всех статусах;
5. напечатает адрес, пароль админа и где лежат пароли дилеров.

Адрес без своего домена — `https://<IP-сервера>.sslip.io`, например
`https://203.0.113.5.sslip.io`. Это бесплатный сервис, который превращает
IP в имя, чтобы Let's Encrypt выдал настоящий сертификат. Замок в браузере
будет зелёным.

**Со своим доменом:** направить A-запись домена на IP сервера и выполнить
`sudo ./deploy/install.sh demo.example.tj`.

**Пустая база** (только админ, без демо-данных): `sudo ./deploy/install.sh --no-demo`.

## 3. Что передать заказчику

- адрес стенда;
- **админку:** логин `admin` и пароль из вывода скрипта (он же в `deploy/.env`,
  строка `ADMIN_PASSWORD`);
- **кабинет дилера:** один-два логина и пароля из `deploy/demo-credentials.txt`.
  Лучше дать дилера с высоким уровнем и участием в акциях, например
  «ООО «Рангсоз»».

Пароли дилеров показываются один раз при заполнении базы и сохраняются только в
этом файле. Потерянный пароль сбрасывается в админке: «Дилеры» → «Доступ» →
«Выпустить новый пароль».

## 4. Обслуживание

Все команды — из папки `deploy/`.

| Что | Команда |
|---|---|
| Обновить до свежего кода | `git pull && sudo ./deploy/install.sh` (пароли и данные сохраняются) |
| Логи | `docker compose logs -f` (или `logs -f backend`) |
| Перезапуск | `docker compose restart` |
| Остановить | `docker compose down` |
| Резервная копия базы | `docker compose exec -T postgres pg_dump -U avtomalyar avtomalyar > backup.sql` |
| Восстановить из копии | `docker compose exec -T postgres psql -U avtomalyar avtomalyar < backup.sql` |
| **Стереть всё и начать заново** | `docker compose down -v && rm .env demo-credentials.txt && sudo ./install.sh` |

## Безопасность

- Снаружи открыты только 80 и 443. База и API доступны лишь внутри
  Docker-сети.
- Cookie сессии — только по HTTPS.
- Попытки входа ограничены для каждого посетителя отдельно: адрес клиента
  передаётся по цепочке Caddy → nginx → API и не подделывается снаружи.
- `deploy/.env` и `deploy/demo-credentials.txt` не попадают в git. Права на них
  — только у root.

## Если что-то не так

- **Сертификат не выпускается:** проверьте, что порты 80/443 открыты в
  файрволе провайдера и что домен смотрит на этот сервер. Смотреть
  `docker compose logs caddy`.
- **Стенд без HTTPS** (например, только внутри сети): в `deploy/.env`
  поставить `SITE_ADDRESS=:80` и `AUTH_COOKIE_SECURE=false`, затем
  `docker compose up -d`. Без второй настройки браузер отбросит cookie, и вход
  не будет держаться.
